DcsQvCull in this repository: where it comes from and how to update it
=======================================================================

What this folder is
-------------------
native/dcsqvcull is the engine module of DCS Control (the DcsQvCull loader and
payload). It was developed in a separate working tree, the "peer" DcsQvCull
folder, and copied in round by round with scripts/vendor-dcsqvcull.ps1
(-Peer <that folder>). The peer tree is not part of this repository and its
location is local to the developer's machine: pass it with -Peer, never write
it into a tracked file.

State on 2026-11-16
-------------------
- The last full copy from the peer was round R147 (commit a8860e2, 2026-10-28:
  DCS 2.9.31 compatibility, regenerated src/hook_sigs.h). The peer's sources
  stop at that date.
- Since then this folder was edited here directly (for example commits
  309732b, a87e75c, c3cb6fd, 2026-11-11 and 2026-11-12: shader warm-up status,
  recorders on emulated command lists, review fixes). Counted on 2026-11-16
  by vendor-dcsqvcull.ps1 -WhatIf: 40 source and test files differ from the
  peer and every one of them is newer here, 19 exist only here, the peer has
  no file this folder lacks.
- So THIS COPY IS AHEAD, and it is the source of truth. A plain re-vendor
  would overwrite newer files with older ones.

How to re-vendor safely
-----------------------
1. Look first, changing nothing:
     .\scripts\vendor-dcsqvcull.ps1 -Peer <peer>\DcsQvCull -Label <round> -WhatIf
   It lists every file that differs, marks the ones that are NEWER HERE, and
   lists the files that exist only here.
2. The script refuses to copy when a file it would overwrite is newer here, or
   when files exist only here. Take only what the peer really changed:
     ... -Label <round> -Only src/<file>,test/<file>
   The newer-here test still applies to the named files.
3. -OverwriteNewer copies everything regardless. Use it only after the peer
   tree has been brought up to this one (copy this folder's src, test, lua and
   tools to the peer first), or to go back on purpose. Step 1 of the script
   snapshots native/dcsqvcull to artifacts/dcsqvcull-snap-<Label> before any
   copy: that folder is the way back.
4. After any copy: scripts/check-contracts.ps1 (the script runs it), then
   scripts/build-dcsqvcull.ps1 and its tests.

Hook signatures (tools/hooks_manifest.json and src/hook_sigs.h)
---------------------------------------------------------------
src/hook_sigs.h is generated by tools/gen_hook_sigs.py from
tools/hooks_manifest.json and the DCS binaries.

- The header here is the R147 one: it records the DCS 2.9.31 build (module
  timestamps 0x6acb...).
- The manifest here is OLDER (2026-10-14, module timestamps 0x6aae..., the
  2.9.30 build): R147 copied the header but not the manifest, because the
  vendor script did not copy it then.
- Regenerating the header from this manifest would take the signatures back
  to the older DCS build. tools/gen_hook_sigs.py now refuses that (a manifest
  older than the header it would replace); --allow-older overrides.
- To put the two in step, either take the peer's manifest
  (vendor-dcsqvcull.ps1 ... -Only tools/hooks_manifest.json; the script copies
  it now) or run tools/extract_manifest.py against the installed DCS and then
  tools/gen_hook_sigs.py. `python tools/gen_hook_sigs.py --check` must then
  pass. Neither was done in the round that wrote this note.

Research documents
------------------
Many source comments cite docs/research/*.md (about 30 documents, cited from
about 40 files). Those documents live in the peer tree only; they are not in
this repository. Read them there, or treat the citation as a pointer to the
round it names.

Shared-memory contracts
-----------------------
The headers this module shares with the other components are listed in
scripts/contracts.json with their canonical copy; scripts/check-contracts.ps1
compares every copy. Change one only on both sides and then record it with
check-contracts.ps1 -Update.
